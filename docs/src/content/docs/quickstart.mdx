This page assumes you've [installed](/installation/) party.js. It takes you from a first burst of confetti to customizing and controlling effects.

## Your first effect

Pass an element to `confetti()`, and confetti bursts out of it:

```js
import { confetti } from "party-js";

const button = document.querySelector("#submit");
button.addEventListener("click", () => confetti(button));
```

<LiveDemo demo="confetti-basic" hideCode size="compact" label="Fire confetti" icon={PartyPopperIcon} />

The confetti comes from the element's whole area, not just its center, so a wide button produces a wide burst. The library draws it on a canvas over the page and removes the canvas again once the last piece is gone.

## Customizing

Every effect takes an options object as its second argument. Options you leave out keep their default:

<LiveDemo demo="confetti-options" size="compact" label="Fire more confetti" icon={PartyPopperIcon} />

Most options accept either a fixed value, like `spread: 120`, or a [sampler](/concepts/samplers/), like `range(80, 120)`, which picks a new random value each time it's used. That's what makes every burst look unique. Each option's documentation says whether it's picked once per burst or once per piece of confetti.

Colors work the same way. Pass a list of color strings and each piece picks one of them:

```js
confetti(button, {
	colors: ["#ff5a5f", "#ffb400", "#00a699", "#7b61ff"],
});
```

Visit [Confetti](/effects/confetti/) for more information on the effect.

## Fire from a point

Instead of an element, you can pass a position in page coordinates, i.e. pixels from the top-left of the document. For example, to fire confetti wherever the user clicks:

```js
area.addEventListener("click", (event) => {
	confetti({ x: event.pageX, y: event.pageY });
});
```

## Sparkles

The other built-in effect is `sparkles()`. It works just like `confetti()`: it takes an element or a point, and an options object. Instead of confetti, it bursts small golden stars out in all directions, unaffected by gravity.

## Control a running effect

Effects start right away and clean up after themselves, so most of the time you can ignore what they return. When you need control, keep the returned effect:

```js
const effect = confetti(button);

effect.pause(); // freezes the particles where they are
effect.resume(); // continues where it left off
effect.stop(); // removes the particles immediately
effect.finished; // a promise that resolves once all particles are gone
```

`stop()` is useful when the element the confetti belongs to goes away, for example when your component unmounts.

## Reduced motion

When a user has asked their system for reduced motion, party.js skips effects by default: nothing is drawn, and your code keeps running as if the effect had played. If your particles carry information the user shouldn't miss, or the user explicitly asked for them, you can play them anyway:

```js
confetti(button, { reducedMotion: "play" });
```

To change the default behavior for every effect, for example from a motion setting on your site, use [`setDefaultReducedMotion()`](/api/effects/setdefaultreducedmotion/).
